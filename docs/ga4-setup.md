# Этап 2 — Google Analytics 4

## Что создаём

- Ресурс: `КВАРЦИТ — сайт`.
- Часовой пояс ресурса: `(GMT+03:00) Moscow`.
- Валюта: российский рубль.
- Веб-поток: адрес опубликованного сайта на Vercel.
- Расширенная статистика: включена; для задания нужны в том числе взаимодействия с формами.

Ресурс создаётся в Google Analytics: **Администратор → Создать → Ресурс**. В ресурсе: **Потоки данных → Добавить поток → Интернет**. В деталях веб-потока скопируйте идентификатор измерения вида `G-...`.

## Подключение к сайту

1. Идентификатор потока для проекта: `G-KMX8WSYJSX`.
2. Он уже записан в `js/config.js`.
3. Опубликуйте изменение сайта через GitHub/Vercel.
4. После публикации откройте сайт и проверьте данные в GA4 → **Администратор → DebugView**.

До публикации обновления сайта GA4 не получает события с сайта. После подключения проверьте, что события появляются в DebugView.

## В GA4 после подключения

Отметить как ключевые события только:

- `generate_lead`
- `contact_click`
- `messenger_click`

Создать определения пользовательских параметров уровня события (Event scope):

| Параметр | Событие |
|---|---|
| `button_name` | `cta_click` |
| `page_section` | `cta_click`, `social_click` |
| `program_name` | `view_program` |
| `tariff_name` | `select_tariff` |
| `lead_direction` | `generate_lead` |
| `messenger` | `messenger_click` |
| `network` | `social_click` |

Созданы все семь пользовательских параметров уровня события. События `generate_lead`, `contact_click` и `messenger_click` появятся в списке GA4 после того, как сайт отправит их хотя бы один раз; тогда для них нужно включить статус ключевого события. В новом ресурсе сняты статусы ключевых событий `close_convert_lead` и `qualify_lead`, добавленные Google по умолчанию.

Проверить в DebugView все обязательные события и параметры из `docs/events.md`. Не регистрировать персональные сведения как параметры GA4: имя, телефон и e-mail в аналитические события не передаются.
